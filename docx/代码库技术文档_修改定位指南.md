## 整体架构分层

```
play (策略层) → behavior_tree (行为树) → tactics (战术逻辑) → soccer_framework (框架基础)
                                               ↓
                                         runtime (运行时装配 & 控制循环)
```

**无环依赖原则**：`soccer_framework` 不依赖任何内部模块，`tactics` 只依赖 `soccer_framework`，`behavior_tree` 依赖 `tactics` + `soccer_framework`，`play` 依赖最上层。

## 二、框架层 `src/soccer_framework/`

该层是整个项目的**基础契约层**，不依赖任何内部模块。

| 文件 | 用途 | 想改什么 → 改这里 |
|------|------|-------------------|
| `types.py` | **核心数据契约** — Pose2D、BallState、GamePhase、MoveIntent、KickIntent 等所有枚举和 dataclass | 增/改数据结构、新增 Intent 类型、改裁判状态枚举 |
| `config.py` | 团队/策略配置 — `SoccerConfig`、`SoccerStrategyTuning`、`SoccerDebugConfig`，从环境变量加载 | 改调参、新增策略旋钮 |
| `game_state.py` | GameController JSON 编解码 (GameControlState ↔ JSON) | GC 协议版本变更、JSON 字段名变更 |
| `ros_truth.py` | ROS 真值订阅适配器 — 订阅 `/teamN/robotX/soccer/sim/ground_truth/...`，提供 PlayContext 快照 | ROS topic 名/消息类型变更 |
| `game_controller.py` | ROS GameController 订阅 — 订阅 `/soccer/game_controller` (std_msgs/String) | GC topic 名/QoS 变更 |
| `ros_adapter.py` | ROS 节点组装/生命周期管理 — 创建/管理 ROS node、executor、spin 线程 | 改 ROS 节点生命周期、换 provider 组合 |
| `robot.py` | 硬件机器人控制 — RobotClient (单机) + TeamRobotManager (多机生命周期/路由) | 改后肢/踢球/模式切换的硬件对接 |
| `telemetry.py` | 结构化日志 — SoccerLogger、JSONL 文件日志、console 输出 | 改日志格式、新增日志通道 |

## 三、战术层 `src/tactics/`

> 纯数学/几何计算，无 BT/ROS 依赖。所有函数都是**纯函数**或**无状态对象**。

| 文件 | 用途 | 想改什么 → 改这里 |

| `geometry.py` | 坐标几何 — Pose2D 工具、TeamFieldFrame (己方球门 x / 对方球门 x / 进攻方向 / 场地 clamp / 球避让) | 改坐标变换规则、场地边界校验 |

## 四、策略层 `src/play/`

> **竞赛策略修改主战场** — 这里是参赛队伍最常修改的层级。

### 4.1 核心入口

| 文件 | 用途 | 想改什么 → 改这里 |
|------|------|-------------------|
| `playbook.py` | **核心策略入口** — Playbook 基类 + DefaultPlaybook：`select_chaser`(追球者选择)、`assign_roles`(角色分配)、`waiting_command`(空闲行为) | **改角色分配逻辑、追球者选择策略 (ball_claim_score + tier-breaking)、空闲行为** |
| `default_roles.py` | **角色行为实现** — ChaserRole (追逐逼近 + 踢球)、SupporterRole (支援位)、DefenderRole (后卫·继承 Supporter)、GoalkeeperRole (守卫 + 清球 + 进攻分支) | **改追逐逼近偏移、守门清球逻辑、各角色具体行为树结构** |
| `play_subtree.py` | PLAY 子树组装工厂 — AssignRoles + 各角色分支 + KickoffHold + PenaltyAvoid + WaitForBall | 改 PLAY 阶段子树结构、增加新前置守卫 |
| `nodes.py` | PLAY 阶段 BT 叶子节点 + AttackSubtree 构建器 — AssignRoles、IsRole、WaitForBall、MoveToTarget、KickAction、build_attack_subtree | 新增 PLAY 阶段条件/动作、改攻击子树结构 |
| `role.py` | 角色策略基类 (RoleStrategy) + 注册中心 (RoleRegistry) | 新增角色能力、改注册约束 |
| `registry.py` | Playbook 注册中心 — 单例 PLAYBOOKS，可 register/unregister/set_default/create | 自定义 Playbook 发现、注册逻辑 |
| `__init__.py` | 包外观 + 注册 DefaultPlaybook 为默认策略 | 注册自定义 Playbook 为默认 |

### 4.2 当前角色职责一览

| 角色 | 类名 | 核心行为 |
|------|------|----------|
| 追球者 | `ChaserRole` | 靠近球 → 进入踢球区 → 踢球/射门/传球 |
| 支援者 | `SupporterRole` | 在球后方支援位等待 |
| 守门员 | `GoalkeeperRole` | 球门守卫 + 防守清球 + 进攻分支 |
| 后卫 | `DefenderRole` | 目前继承 SupporterRole 行为 (骨架) |
