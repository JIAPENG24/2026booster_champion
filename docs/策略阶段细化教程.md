# 策略阶段细化教程

> 本文档教你如何自定义某个比赛阶段的策略行为，以及如何编写高质量的 Prompt 来利用 AI 辅助开发。

---

## 一、阶段系统架构速览

系统的阶段架构分为三层：

```
phases.py                         ← 定义 MatchPhase 枚举 + detect_phase() 检测函数
    ↓
playbook.py: PhasePlaybook       ← 按阶段分发的 playbook，每个阶段有独立方法
    ↓
default_roles.py / targeting/*   ← 角色行为和目标决策（阶段细化时修改的目标）
```

**PhasePlaybook 继承 DefaultPlaybook**，所以所有阶段初始行为和原来完全一致。

核心方法分发表（在 `PhasePlaybook` 中）：

| 阶段                       | 方法名                                  | 初始行为     |
| -------------------------- | --------------------------------------- | ------------ |
| 我方开球                   | `_our_kickoff_assign_roles()`             | DefaultPlaybook |
| 对方开球                   | `_opponent_kickoff_assign_roles()`        | DefaultPlaybook |
| 坠球                       | `_drop_ball_assign_roles()`               | DefaultPlaybook |
| 我方边线球                 | `_our_throw_in_assign_roles()`            | DefaultPlaybook |
| 我方门球                   | `_our_goal_kick_assign_roles()`           | DefaultPlaybook |
| 我方角球                   | `_our_corner_kick_assign_roles()`         | DefaultPlaybook |
| 我方任意球                 | `_our_free_kick_assign_roles()`           | DefaultPlaybook |
| 我方点球                   | `_our_penalty_kick_assign_roles()`        | DefaultPlaybook |
| 对方边线球（防守）         | `_opponent_throw_in_assign_roles()`       | DefaultPlaybook |
| 对方门球（防守）           | `_opponent_goal_kick_assign_roles()`      | DefaultPlaybook |
| 对方角球（防守）           | `_opponent_corner_kick_assign_roles()`    | DefaultPlaybook |
| 对方任意球（防守）         | `_opponent_free_kick_assign_roles()`      | DefaultPlaybook |
| 对方点球（防守）           | `_opponent_penalty_kick_assign_roles()`   | DefaultPlaybook |
| 正常开放比赛               | `_normal_play_assign_roles()`             | DefaultPlaybook |

## 二、如何细化某个阶段的策略

### 步骤 1：创建你的自定义 Playbook

在 `src/play/` 下新建文件（例如 `my_playbook.py`），或直接在一个现有文件中：

```python
# src/play/my_playbook.py

from .playbook import PhasePlaybook, RoleAssignment
from ..soccer_framework import PlayContext


class MyPlaybook(PhasePlaybook):
    """自定义策略：我方开球时让侧翼球员也参与进攻。"""

    # 只覆盖我方开球阶段，其余 13 个阶段自动继承父类行为
    def _our_kickoff_assign_roles(
        self,
        context: PlayContext,
    ) -> RoleAssignment:
        # —— 在这里书写你自定义的逻辑 ——
        # 以下示例：让我方开球时两名球员都去追球
        mapping: dict[int, str] = {}
        for player_id in self.kit.config.player_ids:
            if player_id == self._configured_goalkeeper():
                mapping[player_id] = "goalkeeper"
            else:
                mapping[player_id] = "chaser"  # 所有人都是追球手
        return RoleAssignment(mapping)


    # 再覆盖对方角球阶段的防守策略
    def _opponent_corner_kick_assign_roles(
        self,
        context: PlayContext,
    ) -> RoleAssignment:
        # 让对方角球时全部回防
        # ... 自定义逻辑 ...
        return RoleAssignment(...)
```

### 步骤 2：修改角色行为

除了角色分配，你还可以调整某个阶段下各角色的**具体行为**（如追球方式、射门决策）。

修改 `default_roles.py` 或创建新的角色类，在阶段方法中注册不同的角色组合：

```python
class MyPlaybook(PhasePlaybook):
    def __init__(self, kit):
        super().__init__(kit)
        # 注册阶段特定的角色
        from .default_roles import ChaserRole, SupporterRole, GoalkeeperRole
        from .role import RoleRegistry

        self._kickoff_roles = RoleRegistry()
        self._kickoff_roles.register(ChaserRole())
        self._kickoff_roles.register(GoalkeeperRole())
        # 我方开球时不注册 SupporterRole，所有人都进攻
```

### 步骤 3：注册你的自定义 Playbook

修改 `src/play/__init__.py` 或 `src/runtime.py` 来使用你的 Playbook：

```python
# 方式 A: 在 play/__init__.py 中注册为默认
from .my_playbook import MyPlaybook
PLAYBOOKS.register("default", MyPlaybook, default=True)

# 方式 B: 在 runtime.py 中指定（不推荐，除非你在调试）
self.playbook = MyPlaybook(self.kit)
```

### 完整示例：我方开球时双前锋战术

```python
# src/play/my_playbook.py
from .playbook import PhasePlaybook, RoleAssignment, ROLE_CHASER, ROLE_GOALKEEPER
from ..soccer_framework import PlayContext


class DoubleStrikerPlaybook(PhasePlaybook):
    """我方开球时采用双前锋战术，其余阶段继承默认行为。"""

    def __init__(self, kit):
        super().__init__(kit)
        # 可以在这里注册阶段专用的角色
        # 也可以用 DefaultPlaybook 注册的默认角色

    def _our_kickoff_assign_roles(self, context: PlayContext) -> RoleAssignment:
        # 我方开球：两名非守门员球员都当追球手
        mapping: dict[int, str] = {}
        for player_id in self.kit.config.player_ids:
            if player_id == self._configured_goalkeeper():
                mapping[player_id] = ROLE_GOALKEEPER
            else:
                mapping[player_id] = ROLE_CHASER  # 双前锋！
        return RoleAssignment(mapping)

    def _opponent_kickoff_assign_roles(self, context: PlayContext) -> RoleAssignment:
        # 对方开球：全员防守
        mapping: dict[int, str] = {}
        for player_id in self.kit.config.player_ids:
            if player_id == self._configured_goalkeeper():
                mapping[player_id] = ROLE_GOALKEEPER
            else:
                mapping[player_id] = "defender"  # 使用后卫角色
        return RoleAssignment(mapping)
```

## 三、细化阶段时可修改的文件

根据 `代码库技术文档_修改定位指南.md`，细化特定阶段时通常涉及：

| 修改目标                   | 相关文件                                    |
| -------------------------- | ------------------------------------------- |
| **角色分配（谁做什么）**       | `play/playbook.py` → `_<phase>_assign_roles()` |
| **角色行为（如何做）**         | `play/default_roles.py` → 对应角色类          |
| **射门/传球决策**             | `tactics/targeting/attack.py`               |
| **支援站位**                 | `tactics/targeting/support.py`              |
| **运动控制参数**             | `tactics/motion.py`                         |
| **踢球滞后阈值**             | `tactics/kick_hysteresis.py`               |
| **全局调参**                 | `soccer_framework/config.py` → `SoccerStrategyTuning` |
| **READY 阶段站位**            | `tactics/ready_stance.py`                  |

## 四、如何编写高质量 Prompt（给 AI 的指令）

当你需要 AI 帮助你实现某个阶段的策略细化时，**Prompt 的质量直接决定输出质量**。

### 4.1 好 Prompt 的五大要素

| # | 要素 | 说明 | 示例 |
|---|------|------|------|
| 1 | **明确角色** | 告诉 AI 你希望它以什么身份工作 | "你是一名机器人足球策略工程师" |
| 2 | **给出上下文** | 提供相关代码或文件结构 | "现有默认角色是 Chaser/Supporter/Goalkeeper，见 default_roles.py" |
| 3 | **定义目标** | 清晰描述你想要的行为 | "我方角球时，我希望 Chaser 站到点球区附近，Supporter 站到中圈" |
| 4 | **约束条件** | 规则限制（来自策略红线文档） | "不能违反赛场规则 P-04（防守方距球≥1.45m）" |
| 5 | **输出格式** | 告诉 AI 如何输出结果 | "输出完整的 PhasePlaybook 子类代码，只覆盖 _our_corner_kick_assign_roles 方法" |

### 4.2 Prompt 示例

#### 示例 A：细化角色分配

```
你是一名机器人足球策略工程师。

项目结构：
- PhasePlaybook 继承 DefaultPlaybook，见 src/play/playbook.py
- 默认角色：ChaserRole、SupporterRole、GoalkeeperRole，见 src/play/default_roles.py
- MatchPhase 定义在 src/play/phases.py

目标：
我想覆盖我方角球阶段（_our_corner_kick_assign_roles）的角色分配策略。
我方角球时，我希望：
1. 守门员（player3）保持守门角色
2. 两名非守门员球员都设为追球手（ChaserRole）
3. 不要支援者角色

约束：
- 不能违反 docs/赛场规则.md 中的站位规则
- 必须返回 RoleAssignment 类型

输出格式：
输出一个完整的 MyPlaybook 类，只覆盖 _our_corner_kick_assign_roles 方法。
```

#### 示例 B：细化角色行为（结合战术层）

```
你是一名机器人足球策略工程师。

场景：我方角球时，我希望追球手（Chaser）的踢球目标不是直接射门，
而是先回传给中圈附近的支援者。

相关文件：
- 角色行为：src/play/default_roles.py → ChaserRole.target()、kick_target()
- 射门决策：src/tactics/targeting/attack.py → select_kick_target()
- 传球评分：src/tactics/targeting/attack.py → best_pass_target()
- 配置参数：src/soccer_framework/config.py → SoccerStrategyTuning

请帮我修改 ChaserRole，使其在我方角球阶段（phase == OUR_CORNER_KICK）
时优先寻找传球目标而非直接射门。

输出格式：
1. 需要修改的文件和具体行号
2. 修改后的代码片段
3. 修改说明
```

#### 示例 C：新增调参旋钮

```
请帮我为"我方角球阶段"新增一套独立的踢球滞后阈值。

要求：
1. 在 SoccerStrategyTuning（src/soccer_framework/config.py）中新增字段：
   - corner_kick_enter_distance: float = 2.0（角球时进入踢球距离）
   - corner_kick_exit_distance: float = 2.5（角球时退出踢球距离）
2. 在 PhasePlaybook 中新增方法，在角球阶段使用这些参数
3. 保持默认行为不变

输出格式：
输出完整的修改方案，包含所有需要修改的文件和代码。
```

## 五、调试技巧

### 5.1 验证阶段检测是否准确

在 `_dispatch` 方法中加入临时日志：

```python
def _dispatch(self, phase, context):
    # 临时调试：打印当前检测到的阶段
    logger = self.kit.logger  # 需确保 SoccerKit 有 logger 引用
    if logger is not None:
        logger.info(f"Current phase: {phase.value}", console=True)
    return super()._dispatch(phase, context)
```

### 5.2 验证角色分配是否符合预期

在自定义的 `assign_roles` 方法中：

```python
def _our_kickoff_assign_roles(self, context):
    assignment = RoleAssignment({...})
    # 日志输出
    logger = self.kit.logger
    if logger is not None:
        logger.info(
            f"OUR_KICKOFF roles: {dict(assignment.by_player)}",
            console=True,
        )
    return assignment
```

## 六、常见问题

**Q: 我只想改一个阶段，会不会影响其他阶段？**  
A: 不会。每个阶段有独立的方法，你只覆盖需要改变的那个，其余 13 个阶段自动继承父类的 `_default_assign_roles`。

**Q: 我改了角色分配，但机器人行为没变？**  
A: 检查两点：
1. 是否已注册你的自定义 Playbook 为默认策略（`__init__.py` 中的注册）
2. 机器人行为的改变可能需要同时修改 `default_roles.py` 中的角色类

**Q: detect_phase 检测错了阶段？**  
A: 检查 `GameControlState` 中的 `set_play`、`kicking_team`、`secondary_time` 字段是否如你预期。可以在 `phases.py` 的 `detect_phase()` 中加日志输出。

**Q: 怎么测试某个特定阶段的逻辑？**  
A: 你可以临时修改 `detect_phase()` 强制返回某个阶段值来测试。
